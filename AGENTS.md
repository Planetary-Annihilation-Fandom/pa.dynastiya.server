# Версионирование

Постановки UI-задач должны требовать аудит, понятные исправления и характерные проверки, без обязательных числовых метрик, профилирования и полного обхода экранов. Декоративные пульсации, тени и свечения удаляются по решению пользователя; замеры не являются условием удаления.

Правила работы с интерфейсом находятся в [docs/ui/README.md](docs/ui/README.md). Результат и проверку описывай в сообщении коммита и в комментарии при закрытии issue.

Все задачи «Династии», включая клиентские, веди в [Issues серверного репозитория](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/issues).

В каждом репозитории веди работу в постоянной ветке `dev-<логин>` по GitHub-логину автора в нижнем регистре. Создай её от актуального `dev` при первом использовании и сохраняй после слияния. Из неё открывай PR в `dev`. Сразу после каждого коммита отправляй ветку в `origin` командой `git push -u origin HEAD` при первой отправке и `git push origin HEAD` при последующих.

В `dev` и `main` вливай только через pull request с merge-коммитом. При открытии PR запроси в GitHub ревью у всех коллабораторов-людей с правом записи, кроме автора PR. Слияние требует одобрения каждого из этих ревьюеров и явного разрешения пользователя. Любое другое слияние веток, включая fast-forward, также требует явного разрешения пользователя.

Зависимости из строки «Нужно до начала работ» должны быть влиты в `dev` соответствующего репозитория. Для разрешённого пользователем выпуска открой PR из `dev` в `main` с обновлёнными `version` и `date` в `modinfo.json` изменённой части. После слияния поставь тег и синхронизируй `dev` отдельным PR из `main`. Порядок работы описан в [руководстве](docs/publishing.md).

Версии клиентской и серверной частей ведутся независимо в их `modinfo.json` по схеме `x.y.z`: `x` повышается при существенном нарушении совместимости, `y` — при необходимости миграции сохранённых данных, `z` — при остальных изменениях. Подготовь новую версию и дату выпуска в своей ветке `dev-<логин>` и внеси их в `dev` до слияния релизного PR. Прямое указание пользователя повысить версию сейчас имеет приоритет.
