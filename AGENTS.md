# Версионирование

Задачи обеих частей «Династии» веди в issues серверного репозитория: каждому roadmap соответствует GitHub milestone и корневая issue с меткой `milestone`, от которой строится иерархия sub-issues; всем задачам дерева назначай milestone этого roadmap. Задачи одной темы объединяй под общей issue (например, всё по Legion — под Legion), а общие задачи, затрагивающие несколько тем, выделяй в самостоятельную ветку sub-issues; место в дереве определяй по смыслу, без жёстких критериев.

Постановки UI-задач должны требовать аудит, понятные исправления и характерные проверки, без обязательных числовых метрик, профилирования и полного обхода экранов. Декоративные пульсации, тени и свечения удаляются по решению пользователя; замеры не являются условием удаления.

Правила работы с интерфейсом находятся в [docs/ui/README.md](docs/ui/README.md). Результат и проверку описывай в сообщении коммита и в комментарии при закрытии issue.

Создавай рабочие ветки от `dev`; готовые и проверенные изменения оставляй в рабочей ветке до явного разрешения пользователя на слияние. Любое слияние веток, включая слияние в `dev` или `main` и синхронизацию этих веток, выполняй только с явного разрешения пользователя; просьба выполнить задачу сама по себе такого разрешения не даёт. После разрешения вливай рабочую ветку в `dev` через `--no-ff`, без пулл-реквестов.

Зависимости из строки «Нужно до начала работ» должны быть влиты в `dev` соответствующего репозитория. `main` обновляй только при разрешённом пользователем выпуске: весь `dev` вливается в `main`, релиз отмечается тегом, затем `dev` синхронизируется с `main`; отдельные `chore`- и релизные ветки не создаются. Порядок работы описан в [руководстве](docs/publishing.md).

Версии клиентской и серверной частей ведутся независимо в их `modinfo.json` по схеме `x.y.z`: `x` повышается при существенном нарушении совместимости, `y` — при необходимости миграции сохранённых данных, `z` — при остальных изменениях. Версию изменённой части повышай в коммите релиза, а не в рабочих ветках; прямое указание пользователя повысить её сейчас имеет приоритет.
