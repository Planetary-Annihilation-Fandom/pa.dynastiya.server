# Версионирование

Постановки UI-задач должны требовать аудит, понятные исправления и характерные проверки, без обязательных числовых метрик, профилирования и полного обхода экранов. Декоративные пульсации, тени и свечения удаляются по решению пользователя; замеры не являются условием удаления.

Правила работы с интерфейсом находятся в [docs/ui/README.md](docs/ui/README.md). Результат и проверку описывай в сообщении коммита и в комментарии при закрытии issue.

Для каждой задачи создай рабочую ветку от актуального `dev`. Все изменения по задаче, включая правки после ревью, веди в этой ветке. Сразу после каждого коммита отправляй рабочую ветку в `origin`: при первой отправке выполни `git push -u origin HEAD`, затем используй `git push origin HEAD`.

В `dev` и `main` вливай только через pull request с merge-коммитом. При открытии PR запроси в GitHub ревью у всех коллабораторов-людей с правом записи, кроме автора PR. Слияние требует одобрения каждого из этих ревьюеров и явного разрешения пользователя. Любое другое слияние веток, включая fast-forward, также требует явного разрешения пользователя.

Зависимости из строки «Нужно до начала работ» должны быть влиты в `dev` соответствующего репозитория. Для разрешённого пользователем выпуска открой PR из `dev` в `main`. После слияния поставь тег и синхронизируй `dev` отдельным PR из `main`. Порядок работы описан в [руководстве](docs/publishing.md).

Версии клиентской и серверной частей ведутся независимо в их `modinfo.json` по схеме `x.y.z`: `x` повышается при существенном нарушении совместимости, `y` — при необходимости миграции сохранённых данных, `z` — при остальных изменениях. Версию изменённой части повышай при подготовке выпуска в рабочей ветке по правилам руководства. Прямое указание пользователя повысить версию сейчас имеет приоритет.
