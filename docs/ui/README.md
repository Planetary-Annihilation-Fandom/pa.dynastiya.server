# Правила работы с интерфейсом

Правила распространяются на весь доступный моду HTML/CSS/JS PA, а не только на компоненты «Династии». Приоритет у лобби, главного меню и настроек; редактор систем и арсенал отдельно не прорабатываются без явного запроса. Код UI лежит в [клиентском репозитории](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.client), задачи ведутся в issues этого репозитория.

Начинай с аудита кода и общих правок: общий модуль через `global_mod_list` или точечное переопределение исходного файла сцены. Проверяй по одному характерному примеру каждого изменённого механизма, не обходя все страницы и кнопки. Числовые замеры и профилирование нужны только для конкретной непонятной задержки; декоративные пульсации, тени и свечения убираются по решению пользователя без доказательства ускорения.

Наведение, нажатие, выбор и фокус дают немедленную обратную связь; задержку действия нельзя маскировать анимацией. Длительная операция сразу показывает ожидание, затем результат или ошибку. Область нажатия совпадает с видимым элементом при любом масштабе UI.

Проверка идёт в игре на видимом тестовом профиле: `node mods/dynastiya/tools/resources/launch-test.cjs host` из корня workspace `pa`. Современный браузер не заменяет старый Coherent, поэтому синтаксис и поддержку CSS/API проверяй в игре. Автотесты и постоянные скрипты проверок не пишутся; разовые скрипты держи в `mods/dynastiya/scratchpad/<задача>/`.

Мигание и рывки панелей проверяй по кадру, замороженному через два кадра после изменения: итоговый скриншот показывает уже установившееся состояние и промежуточные кадры не видит.

Режим показа панели (`update`, `replace`, `present`) выбирай по комментариям в клиентских [`presentation.js`](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.client/blob/main/ui/mods/dynastiya.panel_lifecycle/presentation.js) для окон HUD и [`surface.js`](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.client/blob/main/ui/mods/dynastiya.panel_lifecycle/surface.js) для лобби, меню и настроек.

Данные одного матча храни через `dynastiyaMatchStorage`, а матч, армию, лобби и игрока получай через `dynastiyaIds` из клиентского [`dynastiya.context`](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.client/tree/main/ui/mods/dynastiya.context). Хранилище само отделяет матчи и удаляет данные прошлого, поэтому проверять идентификатор лобби в своём коде не нужно.

Результат и проверку описывай в сообщении коммита и в комментарии при закрытии issue. Отдельные отчёты и журналы в `docs/` не ведутся.
