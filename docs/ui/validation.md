# Проверка оптимизаций UI

## Подготовка сравнения

1. Укажи задачу, коммит, сборку игры, backend UI, профиль, разрешение, масштаб UI, режим окна и настройки графики. Опиши сцену, систему, число игроков/юнитов и состояние фоновых программ.
2. Запускай видимый изолированный профиль без кириллицы через `node mods/dynastiya/tools/resources/launch-test.cjs host` из корня workspace `pa`; `host --lobby` дополнительно открывает лобби с тестовыми SVG. Не используй основной профиль игрока. Подробности находятся в `mods/dynastiya/test-profiles/README.md`.
3. Зафиксируй одинаковые длительность и последовательность ввода. Дождись загрузки ресурсов и отдели первый запуск от прогретого. Не меняй одновременно несколько гипотез.
4. Сравни исходный вариант, изменение и возврат исходного варианта; повтори сравнение, если эффект нестабилен. Не путай фоновую загрузку с улучшением от патча.

## Что измерять

| Метрика | Что показывает | Чего не доказывает |
|---|---|---|
| rAF: число кадров, median/p95/max интервала, доля >50 мс | Равномерность цикла UI | Частоту вывода текстуры/монитора |
| Событие ввода → обновление состояния/ближайший rAF | Работу после поступления события в JS | Полную физическую задержку ввода |
| Вход/выход курсора → видимость tooltip, удаление DOM | Задержки и жизненный цикл подсказки | Совпадение JS-событий с выводом пикселей |
| Профиль JS/layout/paint/GC | Стоимость работы и причины пауз в доступном профилировщике | Непосредственно стоимость нативной композиции |
| Видеозамер ввода/изображения или нативная трасса, если доступны | Конечную реакцию и отдельные стадии движка | Причину без дополнительного профилирования |

Сохраняй длительность каждого прогона и число событий. Сравнивай долю длинных кадров или число на секунду; абсолютные количества из прогонов разной длительности не являются одинаковой метрикой. Временные кадры не обрезай без объяснения; прогрев, исключённые интервалы и ввод отладчика указывай отдельно.

## Проверка поведения

Проверь быстрые переходы между соседними элементами, уход курсора, нажатие/удержание, selected/disabled/busy, клавиатурный фокус, подсказки и масштаб UI. Для долгих операций проверь ожидание, ошибку, отмену и поздний ответ; для панелей проверь закрытие/повторное открытие и освобождение ресурсов. В игровом HUD проверь, что ввод не уходит в мир через панель и не блокируется невидимым элементом.

Общую правку проверяй в репрезентативных сценах: меню, лобби, редактор, HUD, настройки. Отмечай непокрытые сцены и отдельные реализации tooltip/контролов. Проверка только лобби не даёт статуса «внедрено во всём UI».

## Запись результата

Для каждой проверенной гипотезы обнови [справочник возможных оптимизаций](optimization-reference.md): публичное основание или локальное наблюдение, способ обнаружения, файлы/компоненты, проверенные варианты, результат и исключения. Отрицательный результат сохраняй; не превращай общую браузерную практику или ответ поисковика в установленный дефект Coherent без основания.

Обнови [журнал](changes.md): задача, дата, область, до/после, условия, ссылка на коммит/PR, ограничения и статус. Исходные JSON/трассы, необходимые для вывода, сохраняй рядом с исследованием в репозитории; временные скриншоты и логи не заменяют итогового объяснения. Отмечай «прототип» до интеграции, «внедрено» после интеграции и проверки, «откачено» при отмене изменения.
