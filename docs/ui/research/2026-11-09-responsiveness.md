# Отзывчивость UI: первичная диагностика

Задача: https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/issues/3. Исходный коммит клиентского исследования: `e1aebea`; результаты перенесены в серверный репозиторий перед закрытием исследовательской ветки. Проверка 2026-11-09, PA 124685, Coherent/Chromium 40, видимый host из AppData, локальное лобби с Dynastiya; система ещё не выбрана, предпросмотр планет не активен.

## Частота и неравномерность кадров

`requestAnimationFrame` обычно выдаёт интервал около 17 мс (примерно 60 Гц), но при обычном оформлении регулярно встречаются интервалы 50–100 мс. Это свидетельство неравномерного JS-цикла кадров, а не доказательство постоянного лимита UI в 30 FPS. Частота передачи текстуры Coherent в игру и вывода готового кадра этим способом не измерена.

Движения мыши подавались через CDP: 30 чередований между соседними кнопками генератора с паузой 150 мс, с переподключением отладчика для каждого ввода. Длительность всего прогона зависит от CDP; количество длинных интервалов между прогонами нельзя сравнивать как одинаковый временной отрезок. Показатель event-to-rAF начинается после получения `mousemove` в JS и не включает очередь нативного ввода, отрисовку, композицию и монитор.

В двух последовательных сравнениях отключение всех CSS-анимаций и переходов снижало p95 интервала кадров примерно с 55–67 до 32–34 мс; после восстановления исходного CSS результат возвращался. Затем отдельно проверены следующие варианты:

| Вариант | p95 интервала rAF, мс | Наблюдение |
|---|---:|---|
| Исходный UI | 53–67 | Регулярные длинные интервалы |
| Без пульсации надписи генератора | 65 | Улучшение не подтверждено |
| Без CSS-переходов | 54 | Улучшение кадров не подтверждено |
| Без CSS-анимаций | 34 | Интервалы стали ровнее |
| Без вращения видимого индикатора загрузки | 34 | Улучшение воспроизвелось |
| Без вращения скрытых индикаторов | 64 | Улучшение не подтверждено |

Вращение индикатора `img.working` — подтверждённый триггер ухудшения rAF в этой конфигурации. Причина внутри рендерера пока не установлена. PNG вместо SVG, 3D-трансформация и ступенчатое вращение улучшения не дали; менять весь набор SVG на PNG оснований нет. Само одноцветное окрашивание SVG не проверялось как причина и не должно считаться ею.

У стандартных `.btn_std:hover`, `.btn_hero:hover`, `.btn_neg:hover`, `.econ-button:hover` в исходных стилях есть переходы 300 мс. У `.btn_std_ix` переход при уходе курсора тоже 300 мс, а наведение мгновенное. У `button.option` генератора вычисленная длительность перехода нулевая. Намеренные переходы и неравномерность кадров — разные факторы.

В `shared/js/api/panel.js` есть период 200 мс, но он управляет обновлением геометрии и видимости встроенных панелей, а не непосредственно частотой CSS-анимаций; трактовать его как 5 FPS всего интерфейса нельзя.

## Общие tooltip

В `shared/js/ko_bindings.js`, `ko.bindingHandlers.tooltip`, заданы `delay.show = 0`, `delay.hide = 100`, `animation = 'fadeIn'`. Последний параметр Bootstrap использует как истинное значение, добавляющее класс `fade`, а не как название отдельной анимации. В `shared/css/global.css` класс `.fade` переопределяет переход на `none`, несмотря на исходные 150 мс в Bootstrap CSS.

Три проверки реальным CDP-наведением на кнопку генератора дали:

- от события `show.bs.tooltip` до `shown.bs.tooltip`: 2,4–6,1 мс; намеренной задержки появления нет;
- от `mouseleave` до `hide.bs.tooltip`: 101,7–102,6 мс;
- при скрытии opacity меняется с 1 на 0 без CSS-перехода;
- удаление невидимого tooltip из DOM происходит ещё примерно через 152 мс: fallback Bootstrap `emulateTransitionEnd(150)`.

Обработчик измерительного `mouseenter` выполнялся после собственного обработчика Bootstrap, поэтому разность `mouseenter → shown` здесь неприменима. Событие `hidden` Bootstrap также не означает фактического удаления узла: удаление проверено MutationObserver.

Общий binding используется по всей игре, но отдельные сцены или моды могут задавать собственные tooltip и переопределять стили. Все игровые сцены визуально не проверялись. Для более быстрой смены подсказок стоит отдельно проверить `hide: 0` и `animation: false`; это предложение, а не уже внесённое глобальное изменение.

## Воспроизведение и оставшиеся вопросы

Запуск: `node mods/dynastiya/tools/resources/launch-test.cjs host --lobby` из корня `pa`. Сохранённые инструменты: [tools](tools/README.md), исходные JSON: [2026-11-09](2026-11-09/). Диагностический `latency-probe.js` выполняется только по явному запуску и не подключён к runtime мода.

Остаются измерение частоты обновления текстуры UI/вывода кадра, длинные кадры с выбранной системой и предпросмотром, а также устранение триггера вращающегося индикатора без потери индикации загрузки. Постоянное исправление задержек на момент исследования не внесено. Исследование #3 завершено; реализация передана в [задачи по доменам](../changes.md). Paperclip на локальном порту 3100 был недоступен при начале работы.
