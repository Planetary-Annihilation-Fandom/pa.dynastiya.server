# Проверка замечаний аудитора: сервер, № 51

Проверено 14 ноября 2026 года по серверному коду `4e1297f`, клиентскому коду `e8e4bb5` и установленным файлам игры. Исходная задача: [№ 51](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/issues/51). Клиентская часть является dependency; ресурсы искались в сервере, клиенте и штатном `media/`.

## Какие сборки и методы использованы

Текущая установленная PA сообщает версию **124685**, Steam BuildID — **25999130**. Декомпилирован загрузчик транспортников именно установленного `bin_x64/server.exe`: программа `current` проекта Ghidra `server`, функция по RVA **0x2b0e40**. Архивная программа `14190493` с PDB использовалась отдельно для чтения именованных загрузчиков частиц и сравнения старого формата транспорта. Steam BuildID и номер из `version.txt` — разные идентификаторы.

| Установленный файл | SHA-256 |
|---|---|
| `bin_x64/server.exe` | `29d94057eef942e5bbe6044d714716cab4a457e6c0f7afb4c44df44ebb54f647` |
| `bin_x64/PA.exe` | `070e086f97114650792f7822fb4fd7f4ef17276b5cdd2546b5615a9e11c6fee8` |

Для текущего `PA.exe` выполнен поиск строк и RIP-relative обращений к ним в исполняемых секциях. Полная декомпиляция его загрузчика частиц не выполнялась. Ниже приведён поясняющий псевдокод восстановленных ветвлений, а не исходный код игры или копия вывода декомпилятора.

## Ложные срабатывания

### Массив точек крепления транспортника — допустим

В `t_transport.json` и `t_transport_adv.json` массив `transporter.transporter_attach_bone` соответствует текущему загрузчику. Установленный `server.exe` различает массив и строку и сохраняет несколько имён креплений:

```cpp
value = json["transporter_attach_bone"];
if (value.isArray())
    for (item : value)
        attachBones.push_back(item.asString());
else if (value.isString())
    attachBones.push_back(value.asString());
```

В архивной сборке `14190493` именованная `TransporterSpec::parse` по RVA `0x2a7740` читает одну строку. Схема отчёта и соответствующая таблица локального справочника не учитывают расширение формата в установленной сборке. Заменять массивы на одну строку по этому замечанию не следует.

### `inheritVelocity` поддерживается отдельно от `inheritedVelocity`

Претензия относится к `uber_charge.pfx`, `weapon_charge.pfx`, `forager_harvest.pfx`, `forager_trail.pfx`, `bug_orb_fighter_charge.pfx` и `bug_mex.pfx`. Именованный загрузчик `crom::ParticleEmitterSpec::parse` архивной сборки читает кривую и булев флаг отдельно:

```cpp
inheritedVelocity = readCurve("inheritedVelocity", 0);
inheritVelocity = readBoolean("inheritVelocity", defaultFromCurve);
```

В текущем `PA.exe` обращения к этим именам найдены по RVA `0x39ade1` и `0x39ae7c`. Утверждение «неизвестный ключ» опровергнуто; переименование булева флага в числовую кривую не является эквивалентной правкой.

### `dead_tin_ded.json` не проигрывает отсутствующие клипы

`aim_down`, `aim_up`, `death01` указаны в узлах `bind_pose`. Узел `playback` воспроизводит клип, а `bind_pose` задаёт исходную позу модели. Единственный `playback` в этом дереве использует существующий `idle`. Формулировка BUG-003 о проигрывании трёх отсутствующих анимаций неверна.

```text
bind_pose + anim_name: aim_down → исходная поза
playback  + anim_name: idle     → существующий клип idle
```

### `sizeX` в `spec` допустим

Часть BUG-008 про `pa/effects/tp.pfx` неверна. Загрузчик `ParticleSpec::parse` поддерживает `sizeX`, `sizeY` и общий `size` внутри `spec`, отдельно от размеров эмиттера. Переносить корректное `spec.sizeX` на уровень эмиттера не следует: это меняет смысл параметра.

Их отсутствие в справочнике аудитора не доказывает отсутствие поддержки. Полное поведение параметров здесь не восстановлено. |

| `splash_damages_allies: "false"` (BUG-014) | Тип неверный. Однако у этого снаряда `damage`, `splash_damage`, `splash_radius` равны нулю; утверждение о текущем уроне союзникам не обосновано. |
| `OffsetY: 0` в двух трассерах (часть BUG-007) | Опечатка есть, но `offsetY` по умолчанию тоже равен нулю. Изменение поведения не установлено. |
| `lable`, пустой ключ в `spec` (часть CON-003) | Это лишние записи; игровая поломка ими не доказана. |
| Разные копии клиентских и серверных ресурсов (CON-001) | Разница файлов не устанавливает неверный результат. Не определено, какая версия должна отображаться; удалять копии автоматически нельзя. |
| Отсутствие 11 сущностей в `unit_list.json` (CON-002) | Пять DOT-сущностей используются через боеприпасы, `bug_wall_acid` — через стену; пять остальных не имеют найденных входящих ссылок. Само отсутствие в списке не доказывает ошибку регистрации. Работа спавна в матче здесь не проверялась. |
| `linkIndex` без типа `EMITTER`, самоссылка эмиттера (CON-005, BUG-011) | Структура подтверждается; нежелательное поведение не воспроизводилось. Автоматическая замена типа не обоснована. |
| Рекомендация `sizeZ → sizeX` (часть BUG-007) | `sizeZ` не является поддерживаемым размером частицы в проверенном формате. Нужная замена не определена: `size`, `sizeX` и `sizeY` задают разный результат. |

## Пример подтверждённой ошибки формата

В пяти эффектах используется `CylinderZ`. Разобранный загрузчик `parseParticleEmitterType` сравнивает имена без учёта регистра, но требует подчёркивание:

```cpp
if (equalsIgnoreCase(value, "CYLINDER_Z"))
    return CylinderZ;
reportUnknownEmitterType();
return Position;
```

Следовательно, `CylinderZ` и `CYLINDER_Z` не эквивалентны. Это ошибка распределения частиц, а не подтверждённая поломка боевой механики.

Проверка выполнена по файлам и загрузчикам. Игра для серверного разбора не запускалась; видимые последствия в бою не воспроизводились. Исправления кода в рамках разбора не вносились.
